The `event` object for the password-reset-post-challenge Actions trigger provides contextual information about the trigger execution.

<table>
  <thead>
    <tr>
      <th>Property</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    
    <tr>
      <td>
        <code>event.authentication</code><br/>
      </td>
      <td>
        Details about authentication obtained during the password reset flow.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>methods</code> <em>Array of objects</em> — Contains the authentication methods a user has completed during their session.<br/>
            Array elements:
            <ul>
              <li>
                One of the following object schemas:
                <ul>
                  <li>
                    An object with the following properties:
                    <ul>
                      <li>
                        <code>name</code> <em>String</em> — The name of the first factor that was completed. Values include:
                        <ul>
                          <li><code>"federated"</code> — A social or enterprise connection was used to authenticate the user as the first factor.</li>
                          <li><code>"pwd"</code> — A password was used to authenticate a database connection user as the first factor.</li>
                          <li><code>"passkey"</code> — A passkey was used to authenticate a database connnection user as the first factor.</li>
                          <li><code>"sms"</code> — A Passwordless SMS connection was used to authenticate the user as the first factor.</li>
                          <li><code>"email"</code> — A Passwordless Email connection was used to authenticate the user as the first factor or verify email for password reset.</li>
                          <li><code>"phone_number"</code> — A phone number was used for password reset.</li>
                          <li><code>"mock"</code> — Used for internal testing.</li>
                          <li><code>string</code> — A custom authentication method denoted by a URL (as second or later factor).</li>
                        </ul>
                      </li>
                      <li>
                        <code>timestamp</code> <em>String</em>
                      </li>
                    </ul>
                  </li>
                  <li>
                    An object with the following properties:
                    <ul>
                      <li>
                        <code>type</code> <em>Optional string</em> — The type of the second (or later) factor that was used for MFA (if available). Values include:
                        <ul>
                          <li><code>email</code></li>
                          <li><code>otp</code></li>
                          <li><code>push-notification</code></li>
                          <li><code>recovery-code</code></li>
                          <li><code>phone</code></li>
                          <li><code>webauthn-roaming</code></li>
                          <li><code>webauthn-platform</code></li>
                        </ul>
                      </li>
                      <li>
                        <code>name</code> <em>The value "mfa"</em> — The user completed multi-factor authentication (second or later factors).
                      </li>
                      <li>
                        <code>timestamp</code> <em>String</em>
                      </li>
                    </ul>
                  </li>
                </ul>
              </li>
            </ul>
          </li>
          <li>
            <code>riskAssessment</code> <em>Dictionary</em> — Supplemental risk assessment. This is available only if the Akamai Integration is enabled and Akamai forwards the headers for the transaction.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>supplemental</code> <em>Dictionary</em> — Supplemental signals sent from third party providers to assist in risk assessments.<br/>
                Includes the following properties:
                <ul>
                  <li>
                    <code>akamai</code> <em>Dictionary</em> — [Limited Early Access] Supplemental risk assessment. This is available only if Akamai Account Protector is enabled and Akamai forwards the headers for the transaction.<br/>
                    Includes the following properties:
                    <ul>
                      <li>
                        <code>akamaiBot</code> <em>Optional object</em> — The bot detection results as forwarded by Akamai Bot Manager.<br/>
                        Includes the following properties:
                        <ul>
                          <li>
                            <code>type</code> <em>String</em> — The type of the Akamai bot manager results.
                          </li>
                          <li>
                            <code>action</code> <em>String</em> — The action of the Akamai bot manager results.
                          </li>
                          <li>
                            <code>botCategory</code> <em>Array of strings</em> — The bot category of the Akamai bot manager results.
                          </li>
                          <li>
                            <code>botScore</code> <em>Number</em> — The bot score of the Akamai bot manager results.
                          </li>
                          <li>
                            <code>botScoreResponseSegment</code> <em>String</em> — The bot score response segment of the Akamai bot manager results.
                          </li>
                          <li>
                            <code>botnetId</code> <em>String</em> — The botnet ID of the Akamai bot manager results.
                          </li>
                        </ul>
                      </li>
                      <li>
                        <code>akamaiUserRisk</code> <em>Dictionary</em> — The user risk detection results as forwarded by Akamai Account Protector.<br/>
                        Includes the following properties:
                        <ul>
                          <li>
                            <code>action</code> <em>String</em> — The action of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>allow</code> <em>Number</em> — The allowed status of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>emailDomain</code> <em>String</em> — The email domain of the user.
                          </li>
                          <li>
                            <code>general</code> <em>Dictionary</em> — The general risk of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>ouid</code> <em>String</em> — The OUID of the user.
                          </li>
                          <li>
                            <code>requestid</code> <em>String</em> — The request ID of the user.
                          </li>
                          <li>
                            <code>risk</code> <em>Dictionary</em> — The risk of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>score</code> <em>Number</em> — The score of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>status</code> <em>Number</em> — The status of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>trust</code> <em>Dictionary</em> — The trust of the Akamai user risk assessment.
                          </li>
                          <li>
                            <code>username</code> <em>String</em> — The username of the user.
                          </li>
                          <li>
                            <code>uuid</code> <em>String</em> — The UUID of the Akamai user risk assessment.
                          </li>
                        </ul>
                      </li>
                    </ul>
                  </li>
                </ul>
              </li>
            </ul>
          </li>
        </ul>
      </td>
    </tr>

        Includes the following properties:
        <ul>
          <li>
            <code>client_id</code> <em>String</em> — The client id of the application the user is logging in to.
          </li>
          <li>
            <code>metadata</code> <em>Dictionary</em> — An object for holding other application properties.
          </li>
          <li>
            <code>name</code> <em>String</em> — The name of the application (as defined in the Dashboard).
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.connection</code><br/>
      </td>
      <td>
        Details about the Connection that was used to authenticate the user.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>id</code> <em>String</em> — The connection's unique identifier.
          </li>
          <li>
            <code>metadata</code> <em>Dictionary</em> — Metadata associated with the connection.
          </li>
          <li>
            <code>name</code> <em>String</em> — The name of the connection used to authenticate the user (such as `twitter` or `some-g-suite-domain`).
          </li>
          <li>
            <code>strategy</code> <em>String</em> — The type of connection. For social connections, `event.connection.strategy === event.connection.name`. For enterprise connections, the strategy is `waad` (Windows Azure AD), `ad` (Active Directory/LDAP), `auth0` (database connections), and so on.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>

        <ul>
          <li>
            <code>domain</code> <em>String</em> — The custom domain name.
          </li>
          <li>
            <code>domain_metadata</code> <em>Dictionary</em> — Custom domain metadata as key-value pairs.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>

      </td>
      <td>

        Includes the following properties:
        <ul>
          <li>
            <code>id</code> <em>String</em> — The Organization identifier.
          </li>
          <li>
            <code>display_name</code> <em>String</em> — The friendly name of the Organization.
          </li>
          <li>
            <code>metadata</code> <em>Dictionary</em> — Metadata associated with the Organization.
          </li>
          <li>
            <code>name</code> <em>String</em> — The name of the Organization.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.prompt</code><br/>
        <p><em>(Optional)</em></p>
      </td>

        Includes the following properties:
        <ul>
          <li>
            <code>id</code> <em>String</em> — The prompt ID.
          </li>
          <li>
            <code>fields</code> <em>Dictionary</em> — Fields and hidden fields data.

          <li>
            <code>vars</code> <em>Dictionary</em> — Shared variables data.
          </li>
        </ul>
      </td>
    </tr>

      <td>
        <code>event.request</code><br/>
      </td>
      <td>
        Details about the request that initiated the transaction.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>body</code> <em>Dictionary</em> — The body of the POST request. This data will only be available during refresh token and Client Credential Exchange flows and Post Login Action.
          </li>
          <li>
            <code>geoip</code> <em>Dictionary</em><br/>
            Includes the following properties:
            <ul>
              <li>
                <code>cityName</code> <em>String</em>
              </li>
              <li>
                <code>continentCode</code> <em>String</em>
              </li>
              <li>
                <code>countryCode</code> <em>String</em>
              </li>
              <li>
                <code>countryCode3</code> <em>String</em>
              </li>
              <li>
                <code>countryName</code> <em>String</em>
              </li>
              <li>
                <code>latitude</code> <em>Number</em>
              </li>
              <li>
                <code>longitude</code> <em>Number</em>
              </li>
              <li>
                <code>subdivisionCode</code> <em>String</em>
              </li>
              <li>
                <code>subdivisionName</code> <em>String</em>
              </li>
              <li>
                <code>timeZone</code> <em>String</em>
              </li>
            </ul>
          </li>
          <li>
            <code>hostname</code> <em>String</em> — The hostname that is being used for the authentication flow.
          </li>
          <li>
            <code>ip</code> <em>String</em> — The originating IP address of the request.
          </li>
          <li>
            <code>language</code> <em>String</em> — The language requested by the browser.
          </li>
          <li>
            <code>method</code> <em>String</em> — The HTTP method used for the request.
          </li>
          <li>
            <code>query</code> <em>Dictionary</em> — The query string parameters sent to the authorization request.
          </li>
          <li>
            <code>user_agent</code> <em>String</em> — The value of the `User-Agent` header received when initiating the transaction.
          </li>
        </ul>
      </td>

          </li>
        </ul>
      </td>
    </tr>

        <code>event.tenant</code><br/>
      </td>
      <td>
        Details about the Tenant associated with the current transaction.<br/>

          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.transaction</code><br/>
      </td>
      <td>
        Details about the current transaction.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>correlation_id</code> <em>String</em> — Correlation ID can be provided in the initial authentication request when the application redirects to Universal Login. You can use value to correlate logs and requests from your Action code with the user flow.
          </li>
          <li>
            <code>locale</code> <em>String</em> — The locale to be used for this transaction as determined by comparing the browser's requested languages to the tenant's language settings.
          </li>
          <li>
            <code>login_hint</code> <em>String</em> — Hint to the Authorization Server about the login identifier the End-User might use to log in (if necessary).
          </li>
          <li>
            <code>state</code> <em>String</em> — An opaque arbitrary alphanumeric string your app adds to the initial request that Auth0 includes when redirecting back to your application.
          </li>
          <li>
            <code>ui_locales</code> <em>Array of strings</em> — The ui_locales provided in the original authentication request.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.user</code><br/>
      </td>
      <td>
        An object describing the user on whose behalf the current transaction was initiated.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>app_metadata</code> <em>Dictionary</em> — Custom fields that store info about a user that influences the user's access, such as support plan, security roles, or access control groups.
          </li>
          <li>
            <code>created_at</code> <em>String</em> — Timestamp indicating when the user profile was first created.
          </li>
          <li>
            <code>email</code> <em>String</em> — (unique) User's email address.
          </li>
          <li>
            <code>email_verified</code> <em>Boolean</em> — Indicates whether the user has verified their email address.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>valueOf</code> <em>() => boolean</em> — Returns the primitive value of the specified object.
              </li>
            </ul>
          </li>
          <li>
            <code>family_name</code> <em>String</em> — User's family name.
          </li>
          <li>
            <code>given_name</code> <em>String</em> — User's given name.
          </li>
          <li>
            <code>last_password_reset</code> <em>String</em> — Timestamp indicating the last time the user's password was reset/changed. At user creation, this field does not exist. This property is only available for Database connections.
          </li>
          <li>
            <code>name</code> <em>String</em> — User's full name.
          </li>
          <li>
            <code>nickname</code> <em>String</em> — User's nickname.
          </li>
          <li>
            <code>phone_number</code> <em>String</em> — User's phone number.
          </li>
          <li>
            <code>phone_verified</code> <em>Boolean</em> — Indicates whether the user has verified their phone number.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>valueOf</code> <em>() => boolean</em> — Returns the primitive value of the specified object.
              </li>
            </ul>
          </li>
          <li>
            <code>picture</code> <em>String</em> — URL pointing to the [user's profile picture](https://auth0.com/docs/users/change-user-picture).
          </li>
          <li>
            <code>updated_at</code> <em>String</em> — Timestamp indicating when the user's profile was last updated/modified.
          </li>
          <li>
            <code>user_id</code> <em>String</em> — (unique) User's unique identifier.
          </li>
          <li>
            <code>user_metadata</code> <em>Dictionary</em> — Custom fields that store info about a user that does not impact what they can or cannot access, such as work address, home address, or user preferences.
          </li>
          <li>
            <code>username</code> <em>String</em> — (unique) User's username.
          </li>
          <li>
            <code>enrolledFactors</code> <em>Dictionary</em> — An array of authentication factors that the user has enrolled. Empty array means the user has no enrolled factors.  If enrolledFactors is undefined, the system was unable fetch the information, the user may or may not have enrolled factors.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>type</code> <em>String</em> — The type of authentication factor such as `push-notification`, `phone`, `email`, `otp`, `webauthn-roaming` and `webauthn-platform`.
              </li>
              <li>
                <code>options</code> <em>Dictionary</em> — Additional options describing this instance of the enrolled factor.
              </li>
            </ul>
          </li>
          <li>
            <code>identities</code> <em>Array of objects</em> — Contains info retrieved from the identity provider with which the user originally authenticated. Users may also link their profile to multiple identity providers; those identities will then also appear in this array. The contents of an individual identity provider object varies by provider.<br/>
            Array elements:
            <ul>
              <li>
                <code>connection</code> <em>String</em> — Name of the Auth0 connection used to authenticate the user.
              </li>
              <li>
                <code>isSocial</code> <em>Boolean</em> — Indicates whether the connection is a social one.<br/>
                Includes the following properties:
                <ul>
                  <li>
                    <code>valueOf</code> <em>() => boolean</em> — Returns the primitive value of the specified object.
                  </li>
                </ul>
              </li>
              <li>
                <code>profileData</code> <em>Dictionary</em> — User information associated with the connection. When profiles are linked, it is populated with the associated user info for secondary accounts.
              </li>
              <li>
                <code>provider</code> <em>String</em> — Name of the entity that is authenticating the user, such as Facebook, Google, SAML, or your own provider.
              </li>
              <li>
                <code>user_id</code> <em>String</em> — User's unique identifier for this connection/provider.
              </li>
            </ul>
          </li>
        </ul>
      </td>
    </tr>
