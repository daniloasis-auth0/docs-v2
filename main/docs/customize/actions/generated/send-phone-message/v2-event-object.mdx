The `event` object for the send-phone-message Actions trigger provides contextual information about the trigger execution.

    <tr>

    <tr>
      <td>
        <code>event.client</code><br/>
        <p><em>(Optional)</em></p>
      </td>
      <td>
        Information about the Client with which this transaction was initiated.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>client_id</code> <em>String</em> — The client id of the application the user is logging in to.
          </li>
          <li>
            <code>metadata</code> <em>Dictionary</em> — An object for holding other application properties.
          </li>
          <li>
            <code>name</code> <em>String</em> — The name of the application (as defined in the Dashboard).
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.custom_domain</code><br/>
        <p><em>(Optional)</em></p>
      </td>
      <td>
        Details about the custom domain associated with the current transaction.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>domain</code> <em>String</em> — The custom domain name.
          </li>
          <li>
            <code>domain_metadata</code> <em>Dictionary</em> — Custom domain metadata as key-value pairs.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.message_options</code><br/>
      </td>
      <td>
        Details about the message that is sent to the user.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>action</code> <em>String</em> — The flow that triggered this action.<br/>
            Possible values include:
            <ul>
              <li><code>enrollment</code></li>
              <li><code>second-factor-authentication</code></li>
            </ul>
          </li>
          <li>
            <code>code</code> <em>String</em> — One-time password that the user needs to use to enter in the form.
          </li>
          <li>
            <code>message_type</code> <em>String</em> — How the message will be delivered, either by 'sms' or 'voice'.<br/>
            Possible values include:
            <ul>
              <li><code>sms</code></li>
              <li><code>voice</code></li>
            </ul>
          </li>
          <li>
            <code>recipient</code> <em>String</em> — Phone number where the message will be sent.
          </li>
          <li>
            <code>text</code> <em>String</em> — Content of the message to be sent.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>

          <li>
            <code>geoip</code> <em>Dictionary</em><br/>
            Includes the following properties:

              </li>

                <code>continentCode</code> <em>String</em>
              </li>

                <code>countryCode</code> <em>String</em>
              </li>
              <li>
                <code>countryCode3</code> <em>String</em>
              </li>
              <li>
                <code>countryName</code> <em>String</em>
              </li>
              <li>
                <code>latitude</code> <em>Number</em>
              </li>
              <li>
                <code>longitude</code> <em>Number</em>
              </li>
              <li>
                <code>subdivisionCode</code> <em>String</em>
              </li>
              <li>
                <code>subdivisionName</code> <em>String</em>
              </li>

                <code>timeZone</code> <em>String</em>
              </li>
            </ul>

          <li>
            <code>hostname</code> <em>String</em> — The hostname that is being used for the authentication flow.

            <code>user_agent</code> <em>String</em> — The value of the `User-Agent` header received when initiating the transaction.

    <tr>
      <td>
        <code>event.security_context</code><br/>
        <p><em>(Optional)</em></p>
      </td>
      <td>
        An object containing fingerprint signatures. This will be available only if the client is using cloudflare. The JA3/JA4 fingerprint can be null or empty in some cases. The most common case is for HTTP requests because JA3 and JA4 are calculated in TLS. It can also be empty due to the Worker sending requests within the same zone or to a zone that is not proxied (or a third party).<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>ja3</code> <em>String</em> — JA3 fingerprint signature. This will be available only if the client is using a TLS connection.
          </li>
          <li>
            <code>ja4</code> <em>String</em> — JA4 fingerprint signature. This will be available only if the client is using a TLS connection.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.tenant</code><br/>
      </td>
      <td>
        Details about the Tenant associated with the current transaction.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>id</code> <em>String</em> — The name of the tenant.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.transaction</code><br/>
        <p><em>(Optional)</em></p>
      </td>
      <td>
        Details about the current transaction.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>correlation_id</code> <em>String</em> — Correlation ID can be provided in the initial authentication request when the application redirects to Universal Login. You can use value to correlate logs and requests from your Action code with the user flow.
          </li>
        </ul>
      </td>
    </tr>
    <tr>
      <td>
        <code>event.user</code><br/>
      </td>
      <td>
        An object describing the user on whose behalf the current transaction was initiated.<br/>
        Includes the following properties:
        <ul>
          <li>
            <code>app_metadata</code> <em>Dictionary</em> — Custom fields that store info about a user that influences the user's access, such as support plan, security roles, or access control groups.
          </li>
          <li>
            <code>created_at</code> <em>String</em> — Timestamp indicating when the user profile was first created.
          </li>
          <li>
            <code>email</code> <em>String</em> — (unique) User's email address.
          </li>
          <li>
            <code>email_verified</code> <em>Boolean</em> — Indicates whether the user has verified their email address.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>valueOf</code> <em>() => boolean</em> — Returns the primitive value of the specified object.
              </li>
            </ul>
          </li>
          <li>
            <code>family_name</code> <em>String</em> — User's family name.
          </li>
          <li>
            <code>given_name</code> <em>String</em> — User's given name.
          </li>
          <li>
            <code>last_password_reset</code> <em>String</em> — Timestamp indicating the last time the user's password was reset/changed. At user creation, this field does not exist. This property is only available for Database connections.
          </li>
          <li>
            <code>name</code> <em>String</em> — User's full name.
          </li>
          <li>
            <code>nickname</code> <em>String</em> — User's nickname.
          </li>
          <li>
            <code>phone_number</code> <em>String</em> — User's phone number.
          </li>
          <li>
            <code>phone_verified</code> <em>Boolean</em> — Indicates whether the user has verified their phone number.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>valueOf</code> <em>() => boolean</em> — Returns the primitive value of the specified object.
              </li>
            </ul>
          </li>
          <li>
            <code>picture</code> <em>String</em> — URL pointing to the [user's profile picture](https://auth0.com/docs/users/change-user-picture).
          </li>
          <li>
            <code>updated_at</code> <em>String</em> — Timestamp indicating when the user's profile was last updated/modified.
          </li>
          <li>
            <code>user_id</code> <em>String</em> — (unique) User's unique identifier.
          </li>
          <li>
            <code>user_metadata</code> <em>Dictionary</em> — Custom fields that store info about a user that does not impact what they can or cannot access, such as work address, home address, or user preferences.
          </li>
          <li>
            <code>username</code> <em>String</em> — (unique) User's username.
          </li>
          <li>
            <code>identities</code> <em>Dictionary</em> — Contains info retrieved from the identity provider with which the user originally authenticates. Users may also link their profile to multiple identity providers; those identities will then also appear in this array. The contents of an individual identity provider object varies by provider.<br/>
            Includes the following properties:
            <ul>
              <li>
                <code>connection</code> <em>String</em> — Name of the Auth0 connection used to authenticate the user.
              </li>
              <li>
                <code>isSocial</code> <em>Boolean</em> — Indicates whether the connection is a social one.<br/>
                Includes the following properties:
                <ul>
                  <li>
                    <code>valueOf</code> <em>() => boolean</em> — Returns the primitive value of the specified object.
                  </li>
                </ul>
              </li>
              <li>
                <code>profileData</code> <em>Dictionary</em> — User information associated with the connection. When profiles are linked, it is populated with the associated user info for secondary accounts.
              </li>
              <li>
                <code>provider</code> <em>String</em> — Name of the entity that is authenticating the user, such as Facebook, Google, SAML, or your own provider.
              </li>
              <li>
                <code>user_id</code> <em>String</em> — User's unique identifier for this connection/provider.
              </li>
            </ul>
          </li>
        </ul>
      </td>
